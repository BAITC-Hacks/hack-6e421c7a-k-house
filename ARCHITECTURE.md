# Архитектурный план TaskBridge AI

## 1. Цель MVP

За 5 часов показать работающий путь:

```
Черновик бизнес-задачи
  → AI-уточнение
  → редактируемая карточка
  → прозрачный рейтинг 0–100
  → публикация в каталоге
  → отклик студенческой команды
  → ручный выбор или отклонение бизнесом
```

Это обязательный сценарий кейса. Всё, что не помогает ему, откладывается.

## 2. Принцип реализации

**Один лёгкий веб-проект, без микросервисов, авторизации и сложного backend.**

Почему:
- на разработку и демо есть только 5 часов;
- кейс разрешает интерактивный прототип с рабочей логикой;
- жюри оценивает сквозной сценарий и прозрачность рейтинга, а не production-инфраструктуру.

## 3. Слои приложения

| Слой | Ответственность | MVP-реализация |
| --- | --- | --- |
| Интерфейс | формы, каталог, отклики, решения бизнеса | `index.html` + `styles.css` |
| Логика | переходы сценария, фильтры, ручной выбор | `app.js` |
| Рейтинг | детерминированный расчёт 0–100 | функция `scoreTask()` |
| AI | вопросы по отсутствующим полям, сбор карточки | локальная безопасная логика сначала; OpenAI API после выдачи ключа |
| Данные | задачи и отклики во время демо | `localStorage` + seed-данные |

## 5. Формула рейтинга

Рейтинг не генерируется AI и не является «чёрным ящиком».

| Условие | Баллы |
| --- | ---: |
| Заполнен контекст и потребность | 20 |
| Указаны данные или материалы | 20 |
| Описан ожидаемый результат | 15 |
| Есть измеримые критерии успеха | 15 |
| Указаны ограничения | 10 |
| Понятны пользователи | 10 |
| Указан контакт и формат взаимодействия | 10 |

**Итого: 100.**

После любого изменения карточки рейтинг пересчитывается. Это даёт сильные 25 баллов за геймификацию бизнеса.

## 6. AI-границы

AI:
- анализирует только текст, который ввёл бизнес;
- задаёт минимум три уточняющих вопроса;
- структурирует подтверждённые ответы в карточку;
- показывает ошибку и позволяет продолжить вручную, если API недоступен.

AI не:
- придумывает данные;
- публикует задачу без подтверждения человека;
- назначает или выбирает команду.

## 7. Этапы работы

### Этап 0 — завершён
- репозиторий и README;
- базовый интерфейс;
- локальная логика рейтинга, каталога и откликов.

### Этап 1 — согласовать и проверить сценарий
- вручную пройти демо от черновика до выбора команды;
- исправить ошибки интерфейса;
- подготовить 5 синтетических задач, 5 команд, 5 откликов.

### Этап 2 — настоящая AI-функция
- добавить endpoint, который получает черновик;
- отправить его OpenAI;
- получить JSON с вопросами или полями карточки;
- валидировать ответ;
- если API не работает — оставить понятный fallback.

### Этап 3 — качество и сдача
- README с инструкцией запуска;
- `.env.example` без ключей;
- тестовый сценарий;
- рабочая ссылка на развёрнутый сайт;
- 5-минутная демонстрация.

## 8. Что не строим

- Telegram-бот;
- логин/регистрацию;
- оплату;
- чат в реальном времени;
- календарь, уведомления и файлы;
- векторную базу;
- отдельную ML-модель;
- автоматическое назначение исполнителя;
- сложную production-инфраструктуру.

## 9. Риски и защита

| Риск | Решение |
| --- | --- |
| Нет API-ключа или API недоступен | рабочая локальная логика и показ промпта/формата входа-выхода |
| Не хватает времени | приоритет только у обязательного сквозного сценария |
| AI придумывает факты | ручное подтверждение и редактирование карточки |
| Сбой на защите | 5 заранее подготовленных локальных задач и откликов |
