# Деление работы 50 / 50

## Рабочее правило

Мы делим проект не по «лёгкой» и «тяжёлой» задаче, а по двум независимым пользовательским сценариям. Каждый участник делает свои коммиты и может показать свою часть жюри.

До начала оба участника вместе за 15 минут:
- подтверждают обязательный сценарий кейса;
- открывают сайт и архитектурные файлы;
- договариваются не менять файлы другого без предупреждения.

---

## Участник A — бизнес-сценарий

**Путь пользователя:** черновик → AI-уточнение → карточка → рейтинг → публикация.

### Задачи

- [ ] Подключить OpenAI для генерации минимум 3 уточняющих вопросов.
- [ ] Получать и валидировать строгий JSON: `questions` и `missingFields`.
- [ ] Сделать fallback: если API не работает, сайт показывает ручные вопросы и не ломается.
- [ ] Связать ответы AI с полями редактируемой карточки.
- [ ] Проверить и отполировать формулу рейтинга 0–100.
- [ ] Показать расшифровку: за что начислены баллы и чего не хватает.
- [ ] Реализовать ручное подтверждение и публикацию задачи.
- [ ] Добавить `.env.example`, не коммитить реальный API-ключ.

### Готово, если

Слабая фраза «Нужен сайт для учёта заказов» проходит до опубликованной карточки с понятным ростом рейтинга.

---

## Участник B — студенческий сценарий

**Путь пользователя:** каталог → фильтр → отклик → решение бизнеса.

### Задачи

- [ ] Подключить `data/seed.json` к интерфейсу.
- [ ] Сделать каталог с сортировкой по рейтингу.
- [ ] Добавить фильтры по теме и уровню готовности.
- [ ] Сделать подробный просмотр карточки задачи.
- [ ] Сделать форму отклика: идея, план, срок, ссылка на прототип.
- [ ] Сделать экран бизнеса со всеми откликами.
- [ ] Реализовать только ручные действия: «выбрать» и «отклонить».
- [ ] Подготовить 5 задач, 5 команд и 5 откликов для надёжного демо.
- [ ] Проверить адаптацию интерфейса на телефоне и ноутбуке.

### Готово, если

Команда находит задачу, отправляет отклик, а бизнес вручную принимает или отклоняет его. Никакого автоматического назначения.

## Финальные 30 минут — вместе

- [ ] Каждый делает финальный commit своей части.
- [ ] Пройти полный демо-путь от начала до конца.
- [ ] Проверить fallback без API.
- [ ] Дописать README: запуск, формула рейтинга, AI-границы, тестовый сценарий.
- [ ] Развернуть сайт и добавить рабочую ссылку в README.
- [ ] Проговорить 5-минутную защиту: каждый объясняет свою половину.

## Правила GitHub

- Один участник — своя область файлов и свои понятные commits.
- Не коммитить `.env` и ключи.
- Перед изменением общего файла (`README.md`, `app.js`) написать друг другу.
